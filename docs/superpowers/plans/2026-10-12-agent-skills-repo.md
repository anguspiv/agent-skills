# agent-skills repository Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A public repo whose `skills/<name>/SKILL.md` files install through both the Claude Code plugin marketplace and skills.sh, with generated catalogs, CI validation, release-please releases, and a Pages index.

**Architecture:** Hand-written `SKILL.md` files are the only source of truth. Pure functions in `scripts/lib/` parse frontmatter, validate, and render every generated file (plugin.json, marketplace.json, README table, docs/index.html). Thin CLIs in `scripts/` wrap them. GitHub Actions run the same CLIs.

**Tech Stack:** Node 22 ESM, `node --test`, zero npm dependencies, release-please, actions/deploy-pages, `claude plugin validate`.

## Global Constraints

- Node `>=22`, no runtime dependencies, `"type": "module"`.
- Skill `name` must equal directory name; `[a-z0-9-]`, 1–64 chars, no leading, trailing, or double hyphen.
- `description` 1–1024 chars. `metadata.version` must be semver.
- Marketplace name and plugin name are both `anguspiv-skills`. Never rename.
- Generated files carry a `generated by scripts/catalog.mjs` marker and are regenerated, never hand-edited.
- Every CLI exits 1 on failure and supports `--help`.

### Task 2: Frontmatter parser

**Files:** Create `scripts/lib/frontmatter.mjs`, `scripts/lib/frontmatter.test.mjs`.

**Produces:** `parseFrontmatter(text: string): { data: Record<string, unknown>, body: string }`. Supports `key: value`, quoted strings, one level of nested maps (`metadata:`), and throws `Error('missing frontmatter')` when the file does not start with `---`.

- [ ] Write tests: parses flat keys, parses nested `metadata`, strips quotes, keeps body, throws without frontmatter.
- [ ] Run `node --test scripts/lib/frontmatter.test.mjs` → FAIL (module not found).
- [ ] Implement. Run again → PASS. Commit `feat(scripts): frontmatter parser`.

### Task 3: Skill discovery and validation

**Produces:** `listSkills(root): Skill[]` where `Skill = { name, dir, data, body }`; `validateSkill(skill): string[]` (empty = valid); `isValidName(name): boolean`; `isSemver(v): boolean`.

### Task 4: validate CLI

**Files:** Create `scripts/validate.mjs`.

**Consumes:** `listSkills`, `validateSkill`. **Produces:** exit 0 with `ok: N skills` or exit 1 listing `skills/<name>: <error>`. Also `staleVersions(root, tag)` in `scripts/lib/git.mjs`: for each skill whose files changed since `tag` and whose `metadata.version` equals the version at `tag`, report an error. Skipped when no `v*` tag exists.

- [ ] Test `git.mjs` with a temp repo created in the test (init, commit skill, tag v0.1.0, edit body without bump → stale; bump → not stale).
- [ ] Implement, run `node scripts/validate.mjs` on the repo → `ok`. Commit `feat(scripts): validate CLI with stale-version check`.

### Task 5: Catalog generators and CLI

**Files:** Create `scripts/lib/catalog.mjs`, `scripts/lib/catalog.test.mjs`, `scripts/catalog.mjs`.

**Produces:** `renderPluginJson({ version, skills })`, `renderMarketplaceJson({ version, skills })`, `renderReadmeTable(skills)`, `replaceBetweenMarkers(text, start, end, inner)`, `renderIndexHtml({ skills, version, repo })`. CLI: default writes all four targets; `--check` exits 1 if any would change; `--bump <skill> <patch|minor|major>` rewrites `metadata.version` in that SKILL.md; `--labels` prints `gh label create` lines.

- [ ] Tests: deterministic JSON (2-space, trailing newline), marketplace entry name equals plugin name, README markers replaced idempotently, HTML contains each skill name and both install commands, HTML escapes `<` in descriptions.
- [ ] Implement. Run `node scripts/catalog.mjs && node scripts/catalog.mjs --check` → exit 0. Commit `feat(scripts): catalog generator`.
